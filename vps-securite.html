Audit de sécurité du VPS

UFW · Fail2banSSH durciIsolation Docker

Documentation de l'état de sécurité du VPS : ce qui est exposé, pourquoi, et les mesures qui réduisent la surface d'attaque. Le principe directeur : ne publier que le strict nécessaire et tout isoler derrière le pare-feu.

SSH

  • Port non standard — réduit drastiquement les tentatives automatisées.
  • Clé uniquement — rend le brute-force inutile.
  • AllowUsers — restreint SSH aux seuls comptes autorisés, même si d'autres comptes système existent.

Authentification par clé uniquement pour tous les comptes, aucune connexion par mot de passe, et les comptes système (www-data…) sont en nologin.

Isolation Docker

Aucun service interne (base de données, cache) n'est exposé sur une interface publique :

  • Redis → 127.0.0.1:7654 uniquement.
  • MariaDB Mailcow → 127.0.0.1:13306 uniquement.
  • MariaDB Nextcloud → réseau Docker interne uniquement.
  • Nextcloud / Collabora → 172.17.0.1 (bridge Docker, inaccessible depuis Internet).

Mises à jour & exploitation

  • unattended-upgrades applique automatiquement les correctifs de sécurité.
  • Mises à jour manuelles régulières ; redémarrage nécessaire après une mise à jour du kernel.
  • Checklist de vérification à effectuer une fois par mois (règles UFW, jails Fail2ban, IP bannies, logs d'accès nginx).
En cas d'incidentBannir manuellement une IP via Fail2ban, consulter la liste des IP bannies, débannir si besoin, et croiser avec les logs d'accès nginx pour qualifier l'activité.
