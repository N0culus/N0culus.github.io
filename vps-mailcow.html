Serveur mail avec Mailcow

DockerPostfix / DovecotDKIM · SPFiptables

Mailcow fournit une messagerie complète (SMTP, IMAP, webmail SOGo, antispam Rspamd) en une pile de conteneurs. Le gros du travail n'est pas l'installation mais la réputation (DNS, DKIM, SPF, reverse DNS) et le fait que Docker contourne le pare-feu.

Installation

cd /opt
sudo git clone https://github.com/mailcow/mailcow-dockerized
cd mailcow-dockerized/
sudo ./generate_config.sh

Réponses au script de configuration :

FQDNmail.privatiq.fr
TimezoneUTC
Branch1 (stable)
IPv6Y
 
sudo docker compose pull
sudo docker compose up -d

L'interface d'administration est ensuite accessible sur https://mail.privatiq.fr. On y ajoute le domaine, puis la clé DKIM via Système → Configuration → Options, qu'on recopie dans les enregistrements DNS chez OVH.

Enregistrements DNS et réputation

Le SPF autorise les serveurs qui ont le droit d'émettre pour le domaine :

MécanismeRôle
mxAutorise le serveur mail du domaine
aAutorise l'adresse du domaine
ip4Bétonne la configuration avec l'IP explicite

Le reverse DNS (PTR) a aussi été corrigé côté OVH pour qu'il corresponde à mail.privatiq.fr : sans PTR cohérent, la plupart des serveurs classent les mails en spam.

Le piège : UFW n'arrête pas Docker

UFW était actif, mais les ports des conteneurs restaient joignables malgré les règles de blocage.

  • UFW filtre la chaîne INPUT.
  • Docker insère ses propres règles dans iptables, sur la chaîne FORWARD.
  • Docker contourne donc UFW.
SolutionFiltrer dans la chaîne DOCKER-USER, qui est évaluée avant les règles de publication de Docker : on y place les DROP voulus, et on vérifie qu'ils apparaissent bien en tête de chaîne. En complément, les ports inutiles ont été commentés dans le docker-compose.yml de Mailcow pour ne plus publier que le strict nécessaire.

Prioriser le SMTP 587 (STARTTLS)

Par défaut, l'autoconfiguration Mailcow annonce le port 465 (SSL implicite) en premier. Pour mettre le 587 (STARTTLS) en priorité :

  1. Éditer le fichier autoconfig.php et inverser l'ordre des deux blocs outgoingServer pour placer 587 / STARTTLS avant 465 / SSL.
  2. Le fichier sur l'hôte ne suffit pas : il faut le copier dans le conteneur php-fpm avec docker compose cp.
  3. Redémarrer php-fpm pour vider le cache opcache, puis vérifier que l'autoconfig renvoie bien 587 en premier.

Mise à jour

sudo ./update.sh
Après une mise à jourLa modification de l'autoconfig vit dans le conteneur : elle est perdue à chaque docker compose pull. Je garde un script post-update.sh dans /opt/mailcow-dockerized/ pour la réappliquer automatiquement après chaque mise à jour.
