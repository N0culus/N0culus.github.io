Nextcloud Talk & Coturn

CoturnTURN / STUNWebRTC

Nextcloud Talk a besoin d'un serveur TURN/STUN pour que la visio traverse les NAT. On installe Coturn, on génère un secret partagé, on ouvre les bons ports — l'étape la plus critique — puis on le branche dans Talk.

Installer l'application et Coturn

Dans Nextcloud : Administration → Applications → Talk → Activer. Puis sur le VPS :

sudo apt install coturn -y

On génère un secret d'authentification (à conserver, il servira dans la config et dans Nextcloud) :

openssl rand -hex 32

Configurer Coturn

Dans /etc/turnserver.conf, on décommente et renseigne : le port d'écoute 3478, le mécanisme d'authentification par secret (use-auth-secret + static-auth-secret), le realm du domaine et l'activation du fingerprint. On active ensuite le service :

sudo systemctl enable --now coturn

Ouvrir les ports (étape critique)

Coturn peut tourner tout en étant injoignable : sans ouverture pare-feu, Talk ne fonctionne pas.

sudo ufw allow 3478/tcp
sudo ufw allow 3478/udp
sudo ufw allow 5349/tcp
sudo ufw allow 5349/udp

Vérifier

Un test de boucle TURN doit afficher Total lost packets 0 (0.000000%).

Configurer Talk dans Nextcloud

Administration → Talk, sans préfixe turn:// ni https:// dans l'URL — uniquement domaine:port :

Serveur STUNValeur
URL<DOMAINE>:3478
Serveur TURNValeur
Protocoleturn: et turns:
URL<DOMAINE>:3478
Secretle secret généré
Protocole réseauUDP et TCP

On teste en rejoignant un appel : si l'appel passe, Coturn est opérationnel.

Faux négatifs connusLe bouton de test ⚡ de l'interface Talk peut afficher un warning orange alors que Coturn fonctionne. De même, les erreurs 401 Unauthorized dans les logs sont normales : elles font partie du protocole d'authentification TURN (challenge-response). On se fie aux logs réels et au test en appel.
