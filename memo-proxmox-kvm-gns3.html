Proxmox avec KVM dans GNS3

Objectif : Configurer GNS3 pour que Proxmox VE (installé dans une VM) puisse utiliser l'accélération KVM, avec vérifications sur l'hôte Ubuntu et commandes dans Proxmox.

🔧 Prérequis

  • Hôte : Ubuntu (avec KVM activé).
  • GNS3 : Installé et configuré avec QEMU.
  • Proxmox VE : Installé dans une VM GNS3 (template QEMU).
  • CPU : Intel (VT-x) ou AMD (AMD-V) avec virtualisation activée dans le BIOS.

✅ Étape 1 : Vérifications sur la machine hôte (Ubuntu)

Avant de configurer GNS3, assurez-vous que l'hôte Ubuntu supporte KVM et la virtualisation imbriquée.

1. Vérifier que la virtualisation est activée dans le BIOS

egrep -c '(vmx|svm)' /proc/cpuinfo
  • Résultat attendu : ≥1 (ex: 4 pour un CPU 4 cœurs avec VT-x). (Si 0, activez VT-x/AMD-V dans le BIOS et redémarrez.)

2. Vérifier que les modules KVM sont chargés

lsmod | grep kvm
  • Résultat attendu :
  • Pour Intel : kvm_intel doit apparaître.
  • Pour AMD : kvm_amd doit apparaître.
  • Si absent, chargez le module manuellement : bash sudo modprobe kvm_intel # Intel # ou sudo modprobe kvm_amd # AMD

3. Activer la virtualisation imbriquée (nested virtualization)

Par défaut, Ubuntu désactive la virtualisation imbriquée pour des raisons de sécurité. Pour l'activer (nécessaire pour que GNS3 puisse transmettre KVM à Proxmox) :

Pour les CPU Intel

# Vérifier l'état actuel (N = désactivé, Y = activé)
cat /sys/module/kvm_intel/parameters/nested

Si le résultat est Y alors passer à l'étape 2.

# Activer la virtualisation imbriquée
echo "options kvm_intel nested=1" | sudo tee /etc/modprobe.d/kvm-intel.conf
sudo modprobe -r kvm_intel
sudo modprobe kvm_intel

# Vérifier que c'est activé
cat /sys/module/kvm_intel/parameters/nested  # Doit afficher "Y"

Pour les CPU AMD

echo "options kvm_amd nested=1" | sudo tee /etc/modprobe.d/kvm-amd.conf
sudo modprobe -r kvm_amd
sudo modprobe kvm_amd
cat /sys/module/kvm_amd/parameters/nested  # Doit afficher "1"

4. Redémarrer l'hôte (optionnel mais recommandé)

sudo reboot

(Cela garantit que les modules KVM sont bien rechargés avec la virtualisation imbriquée activée.)

⚙️ Étape 2 : Configurer GNS3 pour transmettre KVM à Proxmox

Par défaut, GNS3 utilise QEMU en mode émulation (TCG), ce qui ne permet pas à Proxmox d'utiliser KVM. Il faut forcer GNS3 à activer KVM et à exposer les extensions de virtualisation (vmx/svm) à la VM Proxmox.

1. Modifier les paramètres QEMU de la VM Proxmox dans GNS3

  1. Ouvrez GNS3 et démarrez votre projet.
  2. Faites un clic droit sur la VM Proxmox → Configure.
  3. Allez dans l'onglet Advanced.
  4. Dans le champ Options, ajoutez : -enable-kvm -cpu host,+vmx (Remplacez +vmx par +svm si vous avez un CPU AMD.)
  5. Appliquez et redémarrez la VM.

🐧 Étape 3 : Vérifications et commandes dans Proxmox

Une fois la VM Proxmox démarrée, connectez-vous en SSH (ou via la console GNS3) et exécutez ces commandes pour confirmer que KVM est bien détecté.

1. Vérifier que KVM est disponible

kvm-ok
  • Résultat attendu : INFO: /dev/kvm exists KVM acceleration can be used

(Si kvm-ok n'est pas installé, installez-le avec apt install cpu-checker.)

apt update && apt install -y cpu-checker

2. Vérifier que les modules KVM sont chargés

lsmod | grep kvm
  • Résultat attendu : kvm_intel 303104 0 kvm 839680 1 kvm_intel (Pour AMD, vous verrez kvm_amd à la place.)

3. Vérifier les logs du noyau pour KVM

dmesg | grep -i kvm
  • Résultat attendu : [ 0.000000] kvm: already loaded the other module [ 1.234567] kvm: Nested Virtualization enabled [ 1.234568] kvm: VMX/SVM supported (Si vous voyez Nested Virtualization enabled, c'est bon !)
