Sauvegarde & restauration

rsyncSSHincrémental

La solution la plus propre est rsync : il ne copie que ce qui a changé, donc les sauvegardes suivantes sont rapides. Tout part du VPS vers une machine locale, en SSH sur le port custom.

Ce qu'il faut sauvegarder

DossierContenu
/opt/mailcow-dockerized/dataConfigs Mailcow, certificats, nginx custom
/opt/mailcow-dockerized/mailcow.confConfig principale Mailcow
/opt/nextclouddocker-compose.yml + données Nextcloud
/opt/lldapSi installé

Script de sauvegarde

#!/bin/bash
DATE=$(date +%Y-%m-%d)
DEST="/media/leo/DISQUE/sauvegardevps/vps-$DATE"
VPS="leo@IP_VPS"

mkdir -p "$DEST"

echo "=== Sauvegarde Mailcow ==="
rsync -avz -e "ssh -p 51478" --progress \
  --exclude='data/assets/ssl/backups' \
  --exclude='data/Dockerfiles' \
  $VPS:/opt/mailcow-dockerized/data/ "$DEST/mailcow-data/"
rsync -avz -e "ssh -p 51478" $VPS:/opt/mailcow-dockerized/mailcow.conf "$DEST/"

echo "=== Sauvegarde Nextcloud ==="
rsync -avz -e "ssh -p 51478" --progress \
  $VPS:/opt/nextcloud/ "$DEST/nextcloud/"

echo "=== Sauvegarde site vitrine ==="
rsync -avz -e "ssh -p 51478" --progress \
  $VPS:/opt/mailcow-dockerized/data/web/privatiq/ "$DEST/site-privatiq/"

echo "=== Terminé : $DEST ==="

Chaque exécution crée un dossier daté ; grâce à rsync, seules les données modifiées transitent réellement.

Restauration sur un nouveau VPS

Prérequis : un VPS OVH (Ubuntu 24.04), la sauvegarde locale disponible et l'accès SSH au nouveau serveur. La restauration consiste à :

  1. Préparer le nouveau VPS (Docker, arborescence /opt).
  2. Restaurer les données Mailcow et mailcow.conf, puis relancer la pile.
  3. Restaurer Nextcloud (docker-compose.yml + données).
  4. Restaurer le site vitrine.
  5. Réappliquer les modifications manuelles faites dans les conteneurs (elles ne sont pas sauvegardées) — typiquement l'autoconfig SMTP de Mailcow.
  6. Vérifier le fonctionnement des services.
Points clésLe DNS OVH n'a rien à reconfigurer si l'IP du nouveau VPS est identique ; sinon, mettre à jour tous les A et AAAA. Les certificats SSL sont inclus dans la sauvegarde, donc restaurés directement — pas besoin de les régénérer. La base Mailcow (mails, comptes) est dans data/, donc bien couverte.
